# The Current User Guide

**Project Healing Waters event scheduling and participation**

Version: September 13, 2026

## Purpose

The Current is the shared application for viewing events, responding to invitations, managing schedules, recording attendance, and reviewing participation. What you can see and change depends on your assigned role.

## Roles and access

| Role | Typical access |
|---|---|
| Member | Dashboard, notification preferences, events, calendar, RSVP, and eligible Take a Vet Fishing postings |
| Event Creator | Member access plus event creation, event management, assignments, attendance, and event communications |
| Administrator | Event Creator access plus members, groups, imports, reports, templates, and administration |
| TAVF Creator | Create and manage Take a Vet Fishing postings |

Some users belong to more than one program. If prompted after sign-in, select the program you want to work in. Data and permissions follow the selected program.

Only active programs appear in the program picker. A program that is still being prepared may be temporarily unavailable even when an administrator has already created your membership.

## Sign in for the first time

1. Open the invitation or sign-in link provided by your program.
2. Choose **Sign in with Google** or the email one-time-code option.
3. Use the same email address that received the invitation.
4. For first-time email sign-in, choose **Create one** when prompted.
5. Enter the code sent to your email and continue.
6. Select a program if The Current presents the program picker.

If sign-in fails, confirm that the email address matches your member record. Contact your program administrator if you see **No Tenant Access** or do not see expected menu items. **No Tenant Access** means that the signed-in account has no active program membership; it is different from a temporary account-loading error.

## Switch programs, recover a session, and sign out

If you have access to more than one active program, use **Current program** in the header to switch programs. Always confirm the program name in the scope bar before changing members, events, groups, imports, templates, or reports. The page reloads its program data when you switch.

If The Current displays **Your session has expired**, select **Back to sign in** and authenticate again. If it displays **We could not load your account**, select **Try again**. A temporary loading error does not mean that your program access was removed.

Use **Sign out** in the header when you finish, especially on a shared computer. The Current clears its local sign-in and program-selection state during sign-out. If the identity provider cannot finish its sign-out window, close the browser tab before another person signs in.

## Dashboard

The Dashboard is the starting point after sign-in. Use it to:

- review upcoming events;
- see your RSVP activity;
- open event or calendar details;
- access available Take a Vet Fishing opportunities; and
- follow first-time quick-start actions when shown.

## Notification preferences

Open **Preferences** to manage how The Current contacts you.

1. Confirm or enter your mobile number.
2. Choose email, SMS, or both where available.
3. Review the SMS consent statement.
4. Save your preferences.

SMS message frequency varies. Message and data rates may apply. Reply `STOP` to opt out or `HELP` for help. Essential account or policy communication may still be sent by email.

## Find events and RSVP

### From The Current

1. Open **Events** or **Calendar**.
2. Select an event to review its date, location, description, and status.
3. Choose your RSVP response when that action is available.
4. For **Yes**, **Maybe**, or **Waitlist**, select **Volunteer** or **Participant**.

### From an invitation link

1. Open the RSVP link in the email or text message.
2. Review the event details and current RSVP status.
3. Select **Volunteer** or **Participant**.
4. Select **Yes**, **No**, **Maybe**, or **Waitlist**.
5. Wait for the saved-response confirmation before closing the page.

Event leads cannot change their lead RSVP from the public RSVP page; a coordinator manages that assignment.

## Calendar

Open **Calendar** to browse events by month. Event creators can also use calendar exports where offered. Downloaded calendar files identify The Current as the source and can be opened in common calendar applications.

## Take a Vet Fishing

Open **Take a Vet Fishing** to view available postings. Depending on your role and program settings, you may be able to create a posting, review details, or apply to join.

## Event creator workflow

### Create or edit an event

1. Open **Events**.
2. Select **New Event**, or edit an existing event.
3. Select an event category: Fishing Trip, Fundraiser, Community Service, Training, Social, or Other.
4. Enter the title, date and time, location, description, lead, scheduler email, and capacity values.
5. Select the intended invitation audience and notification targets.
6. Save the event as a draft and review it.
7. Publish only when event details and recipients are ready.

Publishing can send invitations. Use update and reminder actions deliberately to avoid duplicate or unnecessary messages.

### Manage RSVPs and assignments

Open the event’s management view. The page contains:

- **Capacity Controls** for volunteer, participant, and total seat limits;
- **Manual Association** for assigning an active member who did not RSVP;
- **Guest Assignments** for guests outside the member roster;
- **RSVP Pool** for ranked member assignment decisions; and
- **Current Assignments** for role, attendance, and removal actions.

Use **Close Event At Capacity** to lock capacity at the current assigned or confirmed counts. Later Yes responses are placed on the waitlist when the applicable capacity is full.

### Assign from the RSVP Pool

1. Select **Prioritize Participant Role** or **Prioritize Volunteer Role**.
2. Review the RSVP role, attendance history, and priority score.
3. Assign the person as a Participant or Volunteer.
4. Confirm that the assignment badge appears.

The priority score is guidance, not an automatic decision. Consider qualifications, accessibility, transportation, safety, and event-specific needs before assigning.

### Record attendance

1. Open **Current Assignments** after the event.
2. Check **Attended** for each person who attended.
3. Make sure the event is marked **completed**.

Attendance history includes only assignments with **Attended** checked on completed events. A checked assignment on a draft or published event does not yet affect history or priority scores.

### Record a volunteer duty or specialty

Each Volunteer assignment can have its own event-specific duty or specialty, such as Cook, Driver, Photographer, Registration, Guide, or Equipment Support.

1. Open the event management page and find **Current Assignments**.
2. Find the assigned Volunteer.
3. Enter the duty under **Volunteer Duty / Specialty**.
4. Select **Save**.

The specialty describes what that person is doing at this event. It does not permanently label the member, and it does not change the service-credit amount: an attended Volunteer assignment earns one service event after the event is completed.

### Reports and summaries

From event management, authorized users can:

- send a lead-preparation summary before the event;
- send a participation summary after completion;
- download CSV and PDF reports; and
- download a roster record.

Review recipients and event status before sending. Post-event actions are available only after completion.

## Understanding CY/PY and priority

**CY** means the current calendar year. **PY** means the previous calendar year. In 2026, for example, CY covers January 1 through December 31, 2026, and PY covers January 1 through December 31, 2025.

### Where the numbers come from

The Current reads historical records from event assignments joined to events. An attendance record counts only when:

- the assignment has **Attended** checked; and
- the related event has status **completed**.

Totals count a member once per event, even if that member had multiple roles. Volunteer history counts completed events attended as a Volunteer. Participant history counts completed events attended as a Participant; if the person was both Event Lead and Participant at the same event, that participant event receives `0.5` credit.

### Columns

| Column | Meaning |
|---|---|
| Volunteer CY/PY | Volunteer attendance credits in the current and previous calendar years |
| Participant CY/PY | Participant attendance credits in the current and previous calendar years |
| Role CY/PY | History for the role shown on the current assignment |
| Total CY/PY | Distinct completed events attended in any role |
| Service CY/PY | Completed events attended as a Volunteer, including fundraisers and community-service events |
| Priority | Rank and calculated equity score for the selected priority role |

### Priority formula

For the selected role:

For Participant priority:

`score = role CY + (role PY × 0.6) + (total CY × 0.25) + (total PY × 0.1) − service CY − (service PY × 0.5) + RSVP adjustment`

For Volunteer priority, the service deduction is not applied because prior Volunteer assignments represent prior workload for that same role.

RSVP adjustment:

| Response | Adjustment |
|---|---:|
| Yes | `-0.2` |
| Maybe | `0` |
| Waitlist | `+0.2` |

Lower scores appear first. Previous-year participation has less weight than current-year participation. Total attendance adds a smaller cross-role weight.

**Example:** A Yes RSVP with `0 / 0` role history and `0 / 0` total history has a score of `-0.2`. If that person is the first-ranked eligible RSVP, the display is `#1 (-0.2)`. This is expected: the score is zero attendance history plus the `-0.2` Yes adjustment.

**Volunteer-service example:** A member who cooked at one completed event and volunteered at two completed fundraisers has three current-year service credits. If they have no Participant history and RSVP Yes for a trip, their score is `0 + 0.75 − 3 − 0.2 = -2.45`. A Yes-only member with no history scores `-0.2`, so the contributing volunteer ranks higher.

### Troubleshooting a score

Check these items in order:

1. Is the historical event marked **completed**?
2. Is **Attended** checked on the member’s assignment?
3. Is the assignment role Volunteer, Participant, or Event Lead?
4. Does the event date fall in CY or PY?
5. Was the member both Event Lead and Participant, which gives `0.5` participant credit?
6. Which priority-role button is selected?
7. Is the RSVP Yes, Maybe, or Waitlist?

After changing attendance or event status, refresh the event management page to retrieve recalculated history.

## Administrator tasks

Administrators have additional navigation under the management menu:

- **Members:** create, update, deactivate, and manage member access.
- **Groups:** maintain targeting groups used for communications and events.
- **Import:** preview and process supported CSV member imports; review import history.
- **Reports:** review participation, delivery, event audit coverage, and exports.
- **Templates:** manage notification templates and history.
- **Admin:** review system health, roles, app access, tenant branding, messaging metadata, program catalog, retention preview, and broadcast tools.

Administrative actions can affect access or send messages to many people. Preview changes and recipient lists before confirming them.

### Large member imports

Use **Import** to preview a supported CSV before committing it.

1. Confirm that the correct program is shown in the header.
2. Preview the file and review invalid rows, shared-email households, and identity conflicts.
3. Commit only after the preview totals match the source file.
4. Download and retain the import report from **Import History**.

For large rollouts, use files of 500-1,000 rows and complete each preview and commit before starting another import. Preview sessions expire after 30 minutes and are lost if the backend is restarted or redeployed.

## Getting help

Use the support or accessibility email shown in The Current footer. When reporting a problem, include:

- the page or event name;
- what you expected to happen;
- what happened instead;
- the approximate time;
- the affected member’s name, but no passwords or one-time codes; and
- a screenshot with sensitive information removed.

Never include passwords, one-time codes, sign-in links, access tokens, full phone numbers, or unmasked member lists in a help request or training screenshot.
